4. SUBMISSION TEXT (paste and edit)

Offload is a workspace that learns the work you repeat so you can hand it over. Its engine, REM, gives an
agent harness a day/night cycle on MongoDB Atlas. By day it runs long tasks durably: checkpoints after every
step, an effects ledger that makes every email exactly-once, and a pause-and-ask when access expires. At night
it replays the day, merges duplicate memories, recalls with Atlas hybrid search ($rankFusion over autoEmbed vectors), stress-tests
itself on harder versions of its own work, and evolves its rules, guardrails and model routing against a
held-out task suite with a no-regression gate. It also grades its own completion evaluator against
deterministic checkers and tunes how strictly it decides a job is done. In the morning it asks once for any new
authority. Measured on Atlas over five simulated days: pass rate 2/4 -> 4/4, collateral 3 -> 0, cost per day
down 90%, memory 32 items instead of 120, zero duplicate emails. Built today: see docs/DEMO-SCRIPT.txt part 1.


5. Q&A

- Real model or scripted? The demo runs a scripted model so the numbers are reproducible and free. Real models
  work through OpenRouter (REM_MODEL=openrouter); a real session today cost $0.02 on the medium tier and
  Rehearse found a real weakness (the project recap missed a shipped item under noisy evidence).
- Why MongoDB? The harness and memory change shape as the system evolves; hybrid search and provenance in one
  aggregation; change streams resume paused runs and drive the live UI; autoEmbed removed the embedding
  pipeline; a transaction plus a unique index gives exactly-once side effects.
- Can it reward-hack its own tests? The gym, fixtures and checkers are read-only to the proposer. Rehearsals
  only reorder or add noise to evidence, never the answer, and held-out tasks are never rehearsed.
- How is this different from Letta sleep-time compute? Sleep here is gated by hard metrics: every edit carries
  a prediction, is validated on held-out tasks, and its prediction error feeds the next night's proposer.
- Does "done" mean done? Calibrate measures it. Without checks, the completion gate called failing runs done
  3 times on train and 2 on held-out on night 1, which is why every task kind needs a checker.
